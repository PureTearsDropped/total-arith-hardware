# ternary_mark — 三値のまま「不明」を桁に持たせる

> ⚠️ **検証前の作業場**（research ブランチ）。生成AI使用。主張には必ず再現コマンドを付けるが、
> `main` の監査済みコードとは別物として扱うこと。

## これは何か

`RESEARCH.md` テーマ1（4値桁 `{0,+1,−1,?}`）に対する **別解**。
**`?` という 4 値目を作らずに**、同じ目的（「不明」を桁に住まわせ、`(値, フラグ)` の
隅に住む監査バグ族を構成的に消す）を果たす。

    語 = [ 溢れの領域 ][ 正規化された仮数 ][ 誤差の領域 ][ 予約桁 ]

**規則は一本**：

> どちらの端も、**端のトリットが無限に続く**と読む。

- 下へ：`Σ2^-k` は**収束** → 有限の端点。`0` なら厳密、`−1` なら下端(GE)、`+1` なら上端(LE)
- 上へ：`Σ2^+k` は**発散** → 溢れ。最上位が `0` なら溢れなし、`±1` なら溢れ（向きは値の符号）

**桁は三値のまま**なので配線正規形（`SPEC` の {−1,0,+1}）を変えない。
フラグ用のビットは **0 本**。

## 相殺の問題と、その解

加算で `−1 + 1` が出会うと `0` になり、「打ち消し合った」と「誤差が無い」が区別できない。
これは一度「結果の桁からは原理的に復元できない」と結論したが、**誤りだった**。

**解**：予約桁を 1 つ確保し、相殺を検出したらそこへ印を下ろす。

- 桁上げは**上へ**流れ、相殺の印は**下へ**流れる。逆向きの二本のリップル
- どちらも隣の桁としか話さない局所規則。**小数点の位置を知る必要がない**
- 予約桁も普通の最下位桁として同じ規則で読む（追加規則ゼロ）
- ずれは常に予約桁 1 つぶんで、相殺が何回起きても**累積しない**

## 検証（すべて再現コマンド付き）

```
python3 total_word.py            # 符号化の自己テスト（往復・不変条件・区間・射影）
python3 cancel_carry_down.py     # 相殺を下へ押す：健全性と緩さ
python3 down_ripple.py           # 下向きリップル == OR 版（6000 例で完全一致）
python3 mul_with_mark.py         # 乗算に同じ仕組みを入れる
python3 div_as_program.py        # 除算は mul と sub の上のプログラム（新規則ゼロ）
python3 total_word_overflow.py   # 溢れ込みの加算（半無限区間）
python3 gate_mark_adder.py       # ゲート段（gate_bilinear の部品のみ）
```

測定値：

| 演算 | 追加した桁規則 | 検証 |
|---|---|---|
| 加算 | 下向きリップル + 予約桁 | 嘘 0（6000 例） |
| 減算 | **ゼロ**（符号反転は配線） | 嘘 0（6000 例） |
| 乗算 | **ゼロ**（同じリップルを足し込み段に） | 嘘 0（3000 例） |
| 除算 | **ゼロ**（候補 = mul と sub の上のプログラム） | 嘘 0（3000 例） |

ゲート段（`gate_mark_adder.py`）：値の経路と Python 模型が一致（値 400 例・印 2000 例で
食い違い 0）。印の経路は値の経路の **17% 前後**（24 桁で 450 対 95）。

溢れ込みの加算では、現行が一律 `SUNK` に落とす 5 件中 **4 件で言えることが増える**
（`[MAX,∞) + 有限` は向きが確定、有限の溢れどうしは有限のまま）。
