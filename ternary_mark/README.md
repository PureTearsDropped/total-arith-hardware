> 「加減乗除すべてで嘘 0」「予約桁 1 つで相殺が完全に捕まる」は**成立しない**。

## これは何か

`RESEARCH.md` テーマ1（4値桁 `{0,+1,−1,?}`）に対する **別解**。
**`?` という 4 値目を作らずに**、同じ目的（「不明」を桁に住まわせ、`(値, フラグ)` の
隅に住む監査バグ族を構成的に消す）を果たす。

    語 = [ 溢れの領域 ][ 正規化された仮数 ][ 誤差の領域 ][ 予約桁 ]

**規則は一本**：

> どちらの端も、**端のトリットが無限に続く**と読む。

- 下へ：`Σ2^-k` は**収束** → 有限の端点。`0` なら厳密、`−1` なら下端(GE)、`+1` なら上端(LE)
- 上へ：`Σ2^+k` は**発散** → 溢れ。最上位が `0` なら溢れなし、`±1` なら溢れ（向きは値の符号）

**桁は三値のまま**なので配線正規形（`SPEC` の {−1,0,+1}）を変えない。
フラグ用のビットは **0 本**。

## 相殺の問題と、その解

加算で `−1 + 1` が出会うと `0` になり、「打ち消し合った」と「誤差が無い」が区別できない。
これは一度「結果の桁からは原理的に復元できない」と結論したが、**誤りだった**。

**解**：予約桁を 1 つ確保し、相殺を検出したらそこへ印を下ろす。

- 桁上げは**上へ**流れ、相殺の印は**下へ**流れる。逆向きの二本のリップル
- どちらも隣の桁としか話さない局所規則。**小数点の位置を知る必要がない**
- 予約桁も普通の最下位桁として同じ規則で読む（追加規則ゼロ）
- ずれは常に予約桁 1 つぶんで、相殺が何回起きても**累積しない**

```
python3 gate_mark_adder.py       # ゲート段（gate_bilinear の部品のみ）
python3 wide_precision.py        # float128 / float256 の幅で回す
```

測定値：

| 演算 | 追加した桁規則 | 検証 |
|---|---|---|
| 加算 | 下向きリップル + 予約桁 | 嘘 0（6000 例） |
| 減算 | **ゼロ**（符号反転は配線） | 嘘 0（6000 例） |
| 乗算 | **ゼロ**（同じリップルを足し込み段に） | 嘘 0（3000 例） |
| 除算 | **ゼロ**（候補 = mul と sub の上のプログラム） | 嘘 0（3000 例） |

ゲート段（`gate_mark_adder.py`）：値の経路と Python 模型が一致（値 400 例・印 2000 例で
食い違い 0）。印の経路は値の経路の **17% 前後**（24 桁で 450 対 95）。

溢れ込みの加算では、現行が一律 `SUNK` に落とす 5 件中 **4 件で言えることが増える**
（`[MAX,∞) + 有限` は向きが確定、有限の溢れどうしは有限のまま）。

## 任意精度 — float128 / float256 は「W を変えるだけ」

規則（padding・下向きリップル・予約桁）はどれも**隣の桁としか話さない**ので、桁数を知らない。
⟹ 仮数桁 W を変えるだけで任意の精度になる。書き換えた規則はゼロ。

```
python3 wide_precision.py
```

| 仮数桁 W | 相当 | 嘘 | ずれ（実測） | 予約桁1つぶんの重み |
|---|---|---|---|---|
| 24 | float32 | 0 | 5.960e-08 | 5.960e-08 |
| 53 | float64 | 0 | 1.110e-16 | 1.110e-16 |
| 113 | **float128** | 0 | 9.630e-35 | 9.630e-35 |
| 237 | **float256** | 0 | 4.528e-72 | 4.528e-72 |
| 512 | — | 0 | 7.458e-155 | 7.458e-155 |

**ずれは常に予約桁 1 つぶんちょうど**（幅によらず一致）。減算も同じ（113/237 桁とも嘘 0）。

費用は桁数に**線形**（桁あたり 38〜51ns で一定）—— 規則が局所であることの直接の帰結。

```
W=24   1.22µs  桁あたり 50.8ns      W=113  4.93µs  桁あたり 43.7ns
W=53   2.31µs  桁あたり 43.7ns      W=237  9.05µs  桁あたり 38.2ns
                                     W=512 20.59µs 桁あたり 40.2ns
```

⟹ 設計の見通し：**加減は桁数に線形／乗算は 2 乗**（実合成の LUT 実測 p=2.149、
2026-08-24）**／精度と範囲は独立**（仮数桁で精度、共有指数の幅で範囲。指数を 8→15bit に
広げるのは実ゲートで +0.018%）。

なお成分に細く割る工夫は**要らない**：分割乗算器を Arty A7-100T 向けに実合成した結果、
面積の利得は無かった（K=24 で 1.04 倍。ゲート呼び出し回数の模型が 4.3 倍と予測したのは
ゼロ詰めを数えていた幻）。**素直に幅を伸ばすのが正解。**
