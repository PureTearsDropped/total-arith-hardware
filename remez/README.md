# remez — 初等関数 = 指数分解 + 係数テープの積和

exp / expm1 / log / sqrt / rsqrt / sin / cos を、Newton の反復でも級数の打ち切りでもなく
**range reduction（指数バスの操作）+ 最良近似多項式（Remez）の Estrin 積和 + 片側境界つきの出口**
で定義し、exp / expm1 / log / sqrt / rsqrt については **端から端までゲート**で組んで spec と bit 一致させた。

到達点を一行で:

- **テープ**: 8 核 × {f32, f64} = 16 本。量子化後の誤差は **有理数だけの証明つき上界**（浮動小数点を使わない）。
- **spec（Level 1）**: 7 関数 × 3 モード（lo / hi / near）を Python 整数だけで定義。全相対誤差の上界 2^-e を
  関数ごとに導出し、出口はその e で片側境界を作る。
- **float32 幅 全入力総当たり**（spec そのもの・双子でない）: 7 関数すべて（exp/expm1 は両符号 42.8 億、他は正の
  21.4 億入力）× 3 モードで **片側境界の違反 0・符号違反 0・厳密の嘘 0**。最悪 ulp は主張の内側（§3 の表: 片側
  1.0005〜1.0039、near 0.5001）。最悪点は 7 関数とも「結果が 2 のべきの直下」。
- **ゲート（Level 2）**: exp / expm1 の 6 出力を f32・f64 で **535 の敵対点すべて spec と bit 一致**
  （フラグ込み・ホスト計算ゼロ）。f32 = 270,592 ゲート・深さ 791、f64 = 687,173 ゲート・深さ 863。
  **log / sqrt / rsqrt** の 9 出力も f32 1461 点・f64 1485 点で bit 一致: f32 = 338,660 / 387,652 / 471,319 ゲート
  （深さ 713 / 610 / 625）、f64 = 1,095,224 / 1,366,904 / 1,536,011（深さ 907 / 800 / 801）。§4.4。

## 1. テープ（`tapes_design.log`）

核は全部「原点で正則・有理係数の冪級数」にしてある（証明で級数の尾を比判定で閉じるため）:
`expm1(r)/r`, `log1p(t)/t`, `√(1+t)`, `1/√(1+t)`, `sin(√y)/√y`, `cos(√y)`。

| テープ | 次数 | ε_remez | ε_量子化 | **ε_証明** | 2^-e | 信号積 | 定数積 | Estrin 深さ |
|---|---|---|---|---|---|---|---|---|
| exp_f32 | 8 | 8.5e-14 | 1.9e-13 | 2.1e-13 | 2^-42 | 6 | 5 | 4 |
| log_f32 | 13 | 2.6e-12 | 2.9e-12 | 6.6e-12 | 2^-37 | 9 | 7 | 4 |
| sqrt_p0/p1_f32 | 12 | 1.4e-12 | 1.8e-12 | 3.5e-12 | 2^-38 | 8 | 7 | 4 |
| rsqrt_p0/p1_f32 | 14 | 9.6e-13 | 1.6e-12 | 2.8e-12 | 2^-38 | 9 | 8 | 4 |
| sin_f32 / cos_f32 | 5 | 4.7e-15 / 6.8e-14 | 5.4e-14 / 2.3e-13 | 5.4e-14 / 2.3e-13 | 2^-44 / 2^-41 | 4 | 3 | 3 |
| exp_f64 | 12 | 3.3e-21 | 9.4e-21 | 1.4e-20 | 2^-65 | 8 | 7 | 4 |
| log_f64 | 22 | 2.1e-19 | 4.2e-19 | 7.7e-19 | 2^-60 | 14 | 12 | 5 |
| sqrt_p0/p1_f64 | 21 | 8.3e-20 | 5.3e-19 / 1.1e-19 | 5.9e-19 / 1.5e-19 | 2^-60 / 2^-62 | 14 | 11 | 5 |
| rsqrt_p0/p1_f64 | 23 | 9.8e-20 | 1.6e-19 / 1.1e-19 | 1.6e-19 / 1.3e-19 | 2^-62 | 15 | 12 | 5 |
| sin_f64 / cos_f64 | 7 | 2.0e-21 / 3.7e-20 | 1.1e-20 / 5.4e-20 | 1.2e-20 / 5.5e-20 | 2^-66 / 2^-63 | 5 | 4 | 3 |

- 「ε_量子化」は密格子上の**実測**（証明でない）。「ε_証明」は `supnorm_exact` の有理数上界で、常に実測 ≥ でない
  こと（ε_証明 ≥ ε_実測）を確認している。
- 同じ関数の 2 片（sqrt/rsqrt の E 偶/奇）は次数を揃えた = 配線が同じでテープだけ差し替え。
- 片側版は多項式を 2 本作らない。`|p−g| ≤ ε|g|` から `g ∈ [p(1−ε), p(1+2ε)]`（ε ≤ 1/2）なので、ε を 2 の冪
  2^-e に切り上げれば **±p·2^-e は指数の付け替え（ゲート 0）+ 加算 1 回**。この e が出口の全予算になる。

## 2. spec の誤差予算と主張（`funcs_spec._budgets`, `claims`）

出口の 2^-e = テープの ε_rig + Estrin の切り捨て上界 + 定数（ln2, π/2, 1/ln2）の丸め + 縮小の切り捨て（全部 Fraction で加算）。

| 関数 | f32: e | near ≤ | lo ≤ | hi ≤ | f64: e | near ≤ | lo ≤ | hi ≤ |
|---|---|---|---|---|---|---|---|---|
| exp | 36 | 0.5002 | 1.0005 | 1.0007 | 60 | 0.5078 | 1.0156 | 1.0234 |
| expm1 | 35 | 0.5005 | 1.0010 | 1.0015 | 59 | 0.5156 | 1.0312 | 1.0469 |
| log | 35 | 0.5005 | 1.0010 | 1.0015 | 58 | 0.5312 | 1.0625 | 1.0938 |
| sqrt | 35 | 0.5005 | 1.0010 | 1.0015 | 59 | 0.5156 | 1.0312 | 1.0469 |
| rsqrt | 33 | 0.5020 | 1.0039 | 1.0059 | 57 | 0.5625 | 1.1250 | 1.1875 |
| sin, cos | 36 | 0.5002 | 1.0005 | 1.0007 | 60 | 0.5078 | 1.0156 | 1.0234 |

（ulp 単位。near ≤ 0.5 + 2^(Wout−e)、lo ≤ 1 + 2^(Wout−e+1)、**hi ≤ 1 + 3·2^(Wout−e)**。hi が 2^j を跨ぐと ulp が
倍になるので跨ぎだけ 2 倍を許す。）

**主張の訂正（正直に書く）**: 最初の hi の主張は lo と同じ式 1 + 2^(Wout−e+1) だった。f32 総当たりで expm1/hi
に 14 件「主張超え」（1.00098〜1.00101 ulp > 1.0009765625）が出て、導出し直したら hi は
v = P(1 + 2^(1−e)) で P 自身が 2^-e を運ぶので **3·2^(Wout−e)** が正しい（値は 1 件も間違っていない・主張の式
が締めすぎだった）。訂正後の判定は再掃引せず、記録した sup（各 (fn,mode) の最悪 ulp）に対して
`sweep_claims_check.py` で行った（sup の単調性で全入力の合否が決まる）。

受け入れ基準（ハンドオフ: f64 ≤ 2 ulp, f32 ≤ 1 ulp + 文書化した余裕）は表の値で満たす。
「1 ulp ちょうど」ではなく **1 + 2^(Wout−e+1) の余裕** が必要な理由: 片側境界は「切り捨て後に 2^-e 分ずらす」
ので、ずらした分の丸めがもう 1 段入る。余裕を 0 にするには e ≥ Wout + 24 程度の核精度が要り、Wk を増やす費用
（Wallace が Wk² で伸びる）に見合わない。

## 4. ゲート実装（`gate_funcs.py`, f32/f64 の exp・expm1）

配線（f32 構成: Win=Wout=24, Wk=40, Pc=56, Q=40, XC=7, kmax=186, EW=13; f64: 53/64/80/64/10/1479/16）:

```
入力 (Win 桁 SD, E バス) → canonicalize(R1) → (大きさ, 符号) → 先頭位置 L（suffix-OR 倍化木）→ ld = L+E
  small (ld ≤ −3): u = x            big (ld ≥ XC): xf = ±2^(XC+Pc) に clamp
  中: xf = N·2^(E+Pc)（左バレル）→ M = |xf|·INV_LN2（定数 Wallace）→ k = ⌊(±M + 2^(Pc+Q−1))/2^(Pc+Q)⌋（配線）
      r = xf − k·LN2（k バス→桁、CSD 配線 + SD 圧縮）→ u = trunc_Wk(r)
Estrin（値は全部 符号-大きさ; SD は加算器の中だけ）: 信号×信号 = 二進 Wallace + 符号 XOR、定数×信号 = 定数の立つ
      ビットの行を Wallace、和 = 窓つき BF 加算（保護桁 G=4, sticky 桁）→ canonicalize → 正規化 Wk
出口: v = 1 + u·q → exp: 2^k = 指数バスへ加算（配線）／ expm1: (v·2^k) − 1 を **k を錨にした窓**（§4.2）
      → finish: v ∓ v·2^-e（定数シフト + 二進加減算）→ 丸め（trunc / away / near-even, 桁上げ再正規化）
      → 溢れ ±MAX / 潰れ ±MIN の mux とフラグ（mode は合成時定数 → 3 本のネットリスト）
```

**差分テスト**（`python gate_funcs.py f32 200`, `f64 200`）: 535 点 = 乱数 200 + 敵対例（small/mid/big の境界、
k=0、|k| ≥ kmax−2、溢れ、Emin で潰れて q=0 / q=±1、expm1 の k < −(Wk+4)、冗長形の入力（値は同じで桁列が違う）、
入力フラグ 8 通り）。**f32・f64 とも 不一致 0・ホスト assert 0**。経路の網羅を marks で確認: small 202 / mid 146
（k=0: 6）/ big 28、溢れ 42/mode、潰れ q=0 と q=±1 の両方、expm1 k<−Gb 47、|k| ≥ kmax−2 36。

### 4.2 設計で起きたこと（順に）

1. **SD で全部持つ版 → 符号-大きさ版**: 最初の版は Estrin の値を符号つき桁（SD）で持ち、f32 で fold 686,310・
   深さ 1011 だった（40×40 の SD 乗算 ≈ 41k が 7 回）。値を演算の間は canonical な符号-大きさに固定し、SD を
   加算器の内部だけに限ると **270,592・深さ 791**（2.5 分の 1）。SD の存在意義は「桁上げが隣で止まる」ことで、
   それは和を取る瞬間にだけ要る。
2. **Wallace の終わり方**: 高さ 3 の列を圧縮すると桁上げが隣に出て隣が 3 になり、層が幅だけ続く（波及＝実質リップル）。
   高さ ≤ 3 で層を止め、最後の 1 層は高さ 2 の列にも半加算器を当てて全列 ≤ 2 にしてから加算器 1 個。
3. **exp(0) と sunk**: spec の exp(0) は「1 を Wout 桁の正規形で」返す（ゲートと同じ表現）。exp > 0 なので入力が
   sunk でも出力の符号は沈まない（値の界だけ 11 で失う）—— docstring の規則どおりに直した。
4. **expm1 の窓（バグ 2 件を単体テストが見つけた）**: (v·2^k) − 1 は位置 0 を底にした窓で厳密に引くのが素直だが、
   f64 では窓幅 ≈ 1548 桁になり expm1 尾が 278k（全体の 30%）を食った。**k を錨にした窓**（幅 Wk+6、位置 Wk+4 が
   相対 0）に変えると 2^k・−1 は one-hot デコーダの 2 行、P·2^k はバレル 1 回、窓の下に落ちるものは sticky 1 桁。
   これで f32 39,854 → 13,978、f64 278,299 → 23,267。
   - 535 点の差分テストは新窓を **通した**が、専用の単体テスト（k を境界値に固定・P を乱数）は 31/667 の不一致を
     出した。①バレル 1 段目の量が枠の前置分を数え忘れて P の下位ビットが落ち残り、借りが消える例。②**P < 0 で
     k ≥ Wk+5** のとき、窓の下に落ちる −|P_low|·2^k − 1 の大きさが 1 単位を超え、sticky の前提（|落ちた量| < 1 単位）
     が破れる例。②の直し: P ≥ 0 は ρ = d − 1（d と 1 の比較）、P < 0 は **窓底に −1 桁を余分に置いて** ρ = (unit−1) − d
     （d と unit−1 の比較）。d の整数ビットと小数部は P のビットに温度計マスク（i < t, i = t, i < hi）を掛けて OR/AND で読む
     （2 段バレルより安い: f32 で 874 ゲート）。直した後 f32 851 例・f64 552 例で不一致 0。
   - 教訓: 差分テストの敵対例は「spec が場合分けする境界」から作っていたので、**ゲート側だけにある境界**（窓の底・
     sticky の切り替え）を踏まなかった。ゲート側の実装が自分の境界を持つなら、その境界の単体テストが要る。
5. **G=4 とホスト assert**: 窓つき加算は「和の先頭位置が窓の底から Wk−1 以上 上」のときだけ厳密。相殺は Estrin の
   節点で 1 桁程度しか起きない（係数は同符号交互の級数）ので G=4 で足りるが、それは**証明でなく assert**
   （破れると bit 一致が壊れてテストで見える）。535 点 × 2 構成で assert 0。expm1 窓にも同じ assert がある。
   → 後に §4.4 で **節点多項式の根が定義域の外**（exp/log/sin/cos: 格子上の最大相殺 < 1 bit）という根拠がつき、
   根のテープ（sqrt/rsqrt）では破れることも分かった。

### 4.3 sin/cos の f64 縮小は引用

Payne–Hanek の窓の分数ビット数は F ≥ Win + fbits + Wk + 2 で、2^-fbits ≤ min|x·2/π − k|。f32 は `fracmin.py` で
**全入力総当たり**（min = 1.028e-9 = 2^-29.9, x = 16367173·2^72）。f64 は総当たり不能で、**binary64 の最悪ケース
（Muller, Elementary Functions §11 / Kahan）を引用**して fbits = 62 とし、その 1 点を mpmath で追検算しただけ。
f64 の全域は検証していない。

### 4.4 log / sqrt / rsqrt のゲート版（`gate_logroot.py`）

exp と同じ部品（canonicalize・先頭位置・バレル・Wallace・窓つき加算・finish）で、縮小だけが違う:

```
入力 → canonicalize → 正規化 Win ビット m（先頭 1 が位置 Win−1）, Ex = E + L      … x = m·2^Ex, m ∈ [1,2)
  log : h = (m の上位 8 ビット ≥ 181)（9 ビット比較器 1 個）  根: h = Ex の最下位ビット（偶奇）
  t = m·2^-h − 1 = m の桁列に位置 Win−1+h の −1 桁を足して canonicalize（厳密）→ 正規化 Wk ビット u、Ex' = Ex + h
  log : q = Estrin(log テープ, u) → P = trunc_Wk(Ex'·LN2·2^-Pc + u·q)   Ex'·LN2 は |Ex'| × 定数（Wallace）、和は窓つき加算
  根  : v = Estrin(p_h, u)  係数を h で選ぶ（p0/p1 は同じ次数）、指数 = v.E ± (Ex' >> 1)（Ex' は偶数 → 配線）
  出口: finish × lo/hi/near（exp と同じ）。x = 0: log → −MAX (1,0,0)、根 → (0, Emin)。x < 0: |x| で計算し 111
  フラグ: Spec._propagate の log/sqrt/rsqrt をそのまま（x ≷ 1 は Ex の符号と m の下位ビットの OR）
```

**差分テスト**（`python gate_logroot.py f32 200`, `f64 200`）: f32 1461 点・f64 1485 点 = 乱数 200 + 敵対例（2 の冪の
2 表現、1 の近傍、top8 = 180/181/182 の境界 × 下位パターン × E、E の偶奇 3 連、完全平方、MIN/MAX、零を E とフラグ
数通りで、冗長桁の零 [(1,1)]×Win、入力フラグ 8 通り、冗長形）。**f32・f64 とも 9 出力すべて 不一致 0・ホスト assert 0**。

| 構成 | 共通 reduce | log（fold / 深さ） | sqrt | rsqrt | 9 出力合計 fold（raw） |
|---|---|---|---|---|---|
| f32 | 1,980 | 338,660 / 713 | 387,652 / 610 | 471,319 / 625 | 1,193,671（1,430,505） |
| f64 | 4,637 | 1,095,224 / 907 | 1,366,904 / 800 | 1,536,011 / 801 | 3,988,865（4,542,803） |

内訳（f32 / f64）: log = reduce 1,855 / 4,071 + Estrin 298,597 / 1,012,577 + 尾（Ex·ln2 + u·q）25,276 / 54,466 +
finish 3 本 10,952 / 19,473。sqrt = reduce 1,796 / 4,012 + Estrin 372,960 / 1,338,962 + 尾（指数の配線）177 / 248 +
finish 10,739 / 19,045。rsqrt = Estrin 456,666 / 1,508,092、他は sqrt と同じ。

**設計で起きたこと（順に）**:

1. **係数を h で選ぶ**: sqrt/rsqrt は E の偶奇でテープが p0/p1 に分かれる。木を 2 本並べる（×2）代わりに、葉の合成時
   定数ビットを h で mux する（等しいビットは定数、違うビットは h か ¬h = 配線 + NOT）。代わりに葉の積が定数積から
   信号積（Wallace 10.4k / 26.2k）になるが、木 1 本分で済む。
2. **p1 テープの係数は Wk より広い**: t ∈ [−½, 0) の単項式基底では |c_k| > 1 で、f32 rsqrt_p1 は 45 ビット、
   f64 sqrt_p1 69・rsqrt_p1 76 ビット（`const_bf` の assert で発覚）。spec が厳密に使う定数なので、ゲートも幅を落とさず
   持つ（`const_bf_wide`、K1）。窓つき加算は幅の違う mag を受ける。
3. **固定 G=4 の窓は根のテープでは足りない（97 件のホスト assert）**: 値は 1461 点すべて spec と一致していたのに、
   窓つき加算の監視「和の先頭 ≥ W」が sqrt/rsqrt の Estrin で 97 回鳴った。原因: Estrin の節点の値は t の多項式で、
   **その根が定義域の内側にあれば節点の相殺は非有界**。`cancel_report` で全テープを調べると:

   | tape | 定義域内の節点根（f32 / f64） | 格子上の最大相殺 bit（f32 / f64） |
   |---|---|---|
   | exp / log / sin / cos | 0 / 0 | 0.3 / 0.8 / 0.2 / 0.5（同じ） |
   | sqrt_p0 / rsqrt_p0 | 0 / 0 | 2.0 / 2.8, 3.5 / **4.4** |
   | sqrt_p1 / rsqrt_p1 | 1 / 4, 2 / 4 | 19.1 / 19.0, 25.1 / 19.6（根で非有界） |

   exp/log/sin/cos の G=4 は「根が外・相殺 < 1 bit」で根拠がついた（以前は assert だけ）。根のテープは p0 でさえ
   f64 rsqrt_p0 が 4.4 bit > G。直し = **窓を下へ Dext = W + extra + 3 − G 桁伸ばす**（extra = 係数の W を超える幅;
   f32 sqrt 39 / rsqrt 44、f64 68 / 75）。正しさ: 小さい側の LSB が窓に入る（d ≤ G+Dext）なら何も落ちず**厳密**
   （相殺の深さは無関係）。落ちる（d > G+Dext）のは先頭位置の差が ≥ 2 のときだけ ⇐ G+Dext ≥ li_S − li_U + 1（最大
   W + extra + 1: 積 2W+extra ビット vs 正規化 W ビット）なので相殺 ≤ 1 bit で「先頭 ≥ W」。+3 は余裕。
   代金: 節点の加算 1 回が f32 13.9k → 22.1k、f64 23.3k → 36.5k（W + 2W ビット）、関数全体で f32 sqrt +25% /
   rsqrt +33%、f64 +23% / +25%（固定 G の数字: f32 297k / 345k、f64 1,087k / 1,208k は監視が破れるので採れない）。
4. **監視条件の正確化**: 旧 assert「常に先頭 ≥ W」は、何も落ちていない厳密な和（積の LSB まで相殺した場合）でも鳴る
   偽陽性があり得た。正しい条件は「**落とした ∧ 先頭 < W**」に直した（exp 側も同じ条件になるが正しさは同値）。
   log の尾 Ex'·ln2 + u·q は |log1p(t)| < 0.347 < ln2/2 なので Ex' ≠ 0 のとき相殺 ≤ 1 bit（固定 G=4 で証明つき）。
5. **R4 の単体テスト**（`test_estrin_mux`）: u と h を直接注入し、`estrin_spec(テープ h, u)` と bit 一致を見る。入力に
   **節点多項式の定義域内の根 ± 1 ulp**（相殺が最も深い点）を足した。f32 73 例・f64 88 例 不一致 0。

## 6. やっていないこと

- sin / cos の**ゲート版**（縮小 = Payne–Hanek の定数 Wallace + 象限 mux。テープの相殺は < 1 bit なので窓は exp と同じ）。
- Estrin の各節点で正規化（trunc_Wk）する現在の形は、節点ごとに canonicalize + 先頭位置 + バレルを払う。固定小数点
  で節点を通し最後に 1 回だけ正規化する形の方が安いはずだが、誤差勘定を作り直す必要があり未評価。
- 合成（LUT 数・Fmax）はしていない。ゲート数は面積の代理にすぎない。
